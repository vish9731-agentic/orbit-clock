# Ringing controls and playback restoration

When Orbit interrupts local media playback, Snooze/Stop ends the alarm audio and releases focus. After the last overlapping alarm ends, Orbit sends one idempotent Android Play command if current playback configurations reported active media (including legacy unknown-usage players) before its Pause command. It does not rely on the legacy stream-activity bit, which can remain true after Pause. Media that was paused, with no other audio playing, is not started. Unexpected service destruction does not explicitly send Play. Routing follows Android's current media-session routing; it cannot guarantee the original session if apps change. Apps must support native media controls. Actual YouTube, casting and physical-device Bluetooth behavior require device acceptance.

## Keep controls above other apps

On the phone, open **Review permissions → Keep alarm controls visible**, then enable Android's **Display over other apps** access for Orbit Clock. This is a user-granted permission; installing an APK does not grant it.

With permission, a persistent phone window offers label/time, occurrence-specific snooze duration, Snooze and Stop. Swiping its header, Back in the app beneath it, and outside touches do not dismiss this window. Home can leave the full-screen activity while these controls stay available. The notification remains as a quiet status/control fallback. The window disappears when the occurrence ends, while the full ringing screen is visible, when locking, on permission revocation or service cleanup.

Without permission, Orbit uses the normal Android alarm notification/full-screen path. Android owns heads-up banner swipe/retraction behavior; FLAG_NO_CLEAR and ongoing flags do not override modern SystemUI policy. No ordinary app can make that native banner impossible to swipe away. Protected system screens can hide overlays, and Home, lock, force-stop and system safety controls remain available.

Back does not finish an active RingActivity. The ringing theme opts out of window swipe-to-dismiss. Existing touch/volume/bezel Snooze/Stop handlers remain; volume shortcuts require the ringing activity to be focused. The existing 30-second clock auto-snooze and timer timeout are retained; they also resolve the occurrence, close controls and restore media when applicable. This update blocks accidental UI dismissal, not those configured automatic actions.

The approved black/amber popup pairs a large time and charcoal duration capsule on the left with Snooze/Stop on the right. The full 64×64dp minus/plus endzones are tappable. The duration remains smaller; the full-width 14sp label wraps without ellipses and exceptionally long content can scroll. When measured widths cannot fit, actions move to a bottom row. +/- adjust only; Snooze is a separate tap. Rotation, enlarged text and window insets retain occurrence selection and reachable controls.

Tapping the time, label, duration center or card padding opens the existing full-screen alarm screen (RingActivity), the screen used when the phone is locked. The launch carries the exact active alarm ID/occurrence and keeps its selected snooze duration. Buttons, including disabled +/- endpoints, consume their touches independently. Canceled taps and scrolling do not navigate; outside-card touches reach the underlying app. The popup remains until RingActivity actually becomes visible, so failed or rejected launches do not remove the controls.

## Verification

The dedicated ringing-session workflow builds a separate same-key native instrumentation APK and independent music/video player. The default UI workflow checks actual alarm delivery, notification PendingIntent actions, overlap/pre-paused guards, playback progress, permitted popup drawing and gesture survival, rendered hierarchy/glyphs, full-label character visibility, balanced control spacing, duration actions, permission revocation, cleanup and portrait/landscape rotation at normal/130% text. A separate tile probe verifies per-alarm next-ring data, minute/format/zone updates, lifecycle, rotation and layout. The approved popup scope passed API35 at100% and130% text, including64dp target corners, disabled endpoint consumption, narrow fallback and real label scrolling. The separate new card-to-full-screen navigation scope records Android accepting RingActivity, then loses the emulator before completion. Navigation and Back/Home must not be described as runtime verified. These fixtures never ship in Orbit. See HANDOFF.md and verification/STATUS.md for the exact passed source/runs; pending or failed runs are not proof.
